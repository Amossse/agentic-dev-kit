## Recent signals and user pain

- GitHub's September 23 Copilot code-review update added ways to request and
  configure automated reviews. Its September 18 update improved review change
  tracking. More automated PR review increases the value of a deterministic
  pre-review scope check. Sources:
  https://github.blog/changelog/month/09-2026/
  https://github.blog/changelog/2026-09-18-copilot-code-review-an-improved-review-experience/
- GitHub announced local sandboxing for Copilot app projects September 23, and
  high-impact proof-of-presence on September 24. These have different scopes
  from a PR policy gate, but reinforce explicit trust boundaries. Sources:
  https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/
  https://github.blog/changelog/2026-09-24-require-proof-of-presence-for-high-impact-actions/

  workflows are increasingly repository-local. Source:
  https://github.com/anthropics/claude-code/releases/tag/v2.1.277
- *Grow the Harness, Not the Context* (September 22) evaluates reusable
  executable controls. Its benchmark is not a PR-security test; the relevance
  here is the pattern of moving recurring decisions into checked code.
  Source: https://arxiv.org/abs/2609.26760
- GitHub Trending snapshot on September 25 surfaced `obra/superpowers` and
  `strands-agents/harness-sdk`; popularity alone did not select this capability.
  Snapshot: https://github.com/trending

GitHub's Actions docs say a default `pull_request` checkout uses a synthetic
merge commit; to inspect only the contributor head, select the event's head
SHA. GitHub separately warns that `pull_request_target` plus untrusted code
and privileged credentials can become a pwn request. Sources:
https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows
https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target

Our Policy Gate v0.6.0 accepts caller-selected `--base` and `--head`. A copied
CI snippet can pick a stale branch name, use GitHub's default merge checkout,
or check a different commit from the event. Users need a narrow, fail-closed
event-to-commit binding rather than another free-form agent instruction.

## Existing solutions and candidates

`dorny/paths-filter` conditionally runs jobs based on changed files;
PR-size labelers label changes for review. They serve different purposes from
enforcing this toolkit's base-owned path/size policy and verifying event head
equals checked-out HEAD. Sources: https://github.com/dorny/paths-filter and
https://github.com/marketplace/actions/pr-size-labeler-action . Community
discussion about oversized agent PRs is anecdotal, not measured demand:
https://www.reddit.com/r/softwarearchitecture/comments/1w0o7g7/how_do_you_handle_oversized_prs/

| Candidate | Relation to matrix | Testable oracle | Decision |
| --- | --- | --- | --- |
| PR Event Gate CLI + reusable workflow | Completes Policy Gate's event-binding gap | Synthetic Git event, SHA mismatch, policy rejection | Build |
| Copilot review-comment adapter | Separate provider API/auth, reviewer semantics | Requires live account and permissions | Defer |
| Agent-skill catalog | Duplicates discovery lists; no engineering gate | No strong behavioral oracle | Reject |

Selected one capability in the main repository. The CLI reads GitHub's event
file, validates strict commit SHAs and checkout identity, then reuses Policy
Gate. The reusable `workflow_call` recipe uses `pull_request`, read-only
permissions, full history and no persisted checkout credentials. It does not
run candidate code, authenticate local event files, or set repository rules.
