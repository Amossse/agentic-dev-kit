## Pain and existing approaches

Observed user pain is not a lack of summaries. It is that scope, size, and test
claims are fragmented and can become stale between an agent finishing and a
human or successor agent consuming the handoff.

Existing approaches reviewed:

- Session/context handoff tools such as `open-grove/handoff` and
  `rosehgal/handoff` preserve narrative and tool context. They solve continuity,
  but narrative context is not the same as re-running repository policy.
- Agent Handoff protocols describe files and collaboration conventions. They are
  richer coordination standards, but adopting a protocol is heavier than adding
  one local delivery gate.
- GitHub artifact attestations, in-toto and SLSA provide authenticated build or
  supply-chain provenance. They are the right answer for adversarial provenance,
  but they do not replace a developer's local branch-scope, review-size and
  state-bound-test policy.
- The toolkit already had Staged Scope, Range Scope, Test Proof and Diff Budget.
  Each produces useful evidence, but the reviewer still had to recover their
  original parameters and determine whether all reports referred to the same
  current state.

## Selection and differentiation

Selected: **Handoff Proof**, an offline developer CLI in the flagship repository.

It fills the matrix gap between individual evidence gates and a consumable
handoff. `create` records one explicit task policy only after Range Scope, Diff
Budget and Test Proof all pass. `verify` validates the bounded manifest, re-runs
the recorded policy, and requires exact evidence equality. The manifest stays in
Git metadata so writing it does not invalidate its own test evidence.

The differentiator is deliberately narrow: executable, state-bound policy
composition without collecting conversations, invoking a model, inventing a new
handoff protocol, or claiming signed provenance. The implementation remains one
stdlib module over existing checked primitives.
