## Pain, alternatives, and gap

Handoff Proof v0.5.0 records the creator's own `--allow` paths and budgets. In
a PR check, an agent or contributor could choose a permissive policy and still
produce a valid manifest. A repository owner needs the current base branch's
policy to control the submitted branch.

GitHub CODEOWNERS, branch protection, and required status checks establish
approval and merge authority; they do not by themselves calculate this
toolkit's path and diff-size decisions. Source:
https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners

Existing broader solutions include `yonk-labs/bob` (agent build/verify loop
with allowed paths and changed-line budgets), `rodrigojager/code-approval-gates`
(quality/semantic gates and policy JSON), and
`shihchengwei-lab/coding-agent-guardrails` (install-once agent guardrails).
These informed a narrow addition instead of another orchestration framework.
Sources:

- https://github.com/yonk-labs/bob
- https://github.com/rodrigojager/code-approval-gates
- https://github.com/shihchengwei-lab/coding-agent-guardrails

Community threads on AI-specific CODEOWNERS and repo-local policy describe the
same separation of PR author and policy owner, but remain anecdotal:
https://www.reddit.com/r/SideProject/comments/1u9efo7/i_made_codeowners_for_ai_agents/

## Candidate decisions

| Candidate | Matrix relation | Observable oracle | Decision |
| --- | --- | --- | --- |
| Base policy gate | Completes Handoff Proof's self-declared policy gap | Read base blob; run existing path and size gates; reject policy edits | Build |
| Coverage ruleset adapter | Would duplicate GitHub API work and require auth | Available official REST API | Defer |
| Agent sandbox config generator | OS and vendor semantics vary | No small cross-platform oracle | Defer |
| Signed handoff | Needs identity and signing infrastructure | in-toto/SLSA already exist | Defer |

Selected capability: **Policy Gate**, a Python stdlib + Git CLI in the main
repository. It reads a fixed policy file from the caller's base commit, strictly
validates it, and applies the existing Range Scope and Diff Budget checks to a
single resolved head. A candidate policy edit is an explicit rejection.

It does not authenticate the base ref or set GitHub protections. The intended
deployment uses the PR event's base SHA, a required check, and owner review for
policy/workflow changes. A local invocation is an advisory check.
