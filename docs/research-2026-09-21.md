## Existing solutions and differentiation

- CI systems already record a job against a commit SHA. They are the right answer
  after push. Test Proof covers the local dirty/staged state before a commit or PR,
  with no provider, token, workflow file, or network dependency.
- `pytest`, `unittest`, `go test` and similar tools own test execution. Test Proof
  wraps any explicit argument array; it does not replace their reporting.
- Build provenance systems such as SLSA address artifact supply-chain provenance.
  This module is deliberately smaller: one command result plus a local Git-state
  fingerprint, with no signing or remote attestation claim.
- Generic command loggers record output and timing but may not establish that the
  repository remained unchanged. Test Proof snapshots before and after, rejects
  pre-existing untracked files, and later verifies the same represented state.
- A plain `git rev-parse HEAD` misses staged and unstaged tracked edits. Test Proof
  combines HEAD with a fixed binary/full-index diff hash and untracked-file count.

## Candidate choice

| Candidate | Decision |
| --- | --- |
| State-bound test receipt | Selected: documented matrix gap, deterministic, provider-neutral, one-day scope |
| AI review-finding delta | Rejected today: GitHub and mature reviewers already track review rounds; stable cross-vendor identity remains ambiguous |
| Claude review export Skill | Deferred: upstream UI artifact is not exposed as a stable local input |
| Full CI repair agent | Rejected: provider auth, hostile logs, mutation controls and realistic evals exceed the bounded release |
| MCP disconnect recorder | Deferred: needs multiple live clients/servers and protocol fixtures |

Test Proof stays inside the main repository and reuses its fixed Git execution,
error contract, package, tests and release path. It fills the test-evidence column
without creating another repository. Suggested discovery additions: `testing`,
`test-automation`, `software-supply-chain`; launch copy remains manual-only.
