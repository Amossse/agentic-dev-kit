# 2026-09-30 research and decision

Search window: 2026-09-23 through 2026-09-30. Terms: Claude Code, coding
agents, MCP, GitHub Actions artifacts, digest, expired artifacts, CI provenance,
code review, GitHub Trending, developer workflow evidence.

## Signals

- GitHub [stopped showing expired Actions artifacts in the UI and API on
  September 24](https://github.blog/changelog/2026-09-24-expired-github-actions-artifacts-no-longer-shown-in-ui-and-api/).
  Missing artifacts and expired metadata need explicit error handling.
- GitHub's [Actions artifact REST API](https://docs.github.com/en/rest/actions/artifacts)
  exposes artifact ID, expiry, SHA-256 archive digest, and the associated run
  ID/head SHA. Its [artifact documentation](https://docs.github.com/en/actions/tutorials/store-and-share-data)
  identifies the digest as the uploaded artifact archive's digest.
- GitHub [moved self-hosted runner version enforcement to September 29](https://github.blog/changelog/2026-09-28-self-hosted-runner-version-enforcement-date-has-moved/).
  This was considered as a separate runner-compatibility check, but is not the
  strongest gap in this toolkit.
- GitHub [made Claude Sonnet 5.5 available in Copilot on September 28](https://github.blog/changelog/2026-09-28-claude-sonnet-5-5-in-github-copilot/).
  More agent-generated work increases the need to bind handoff evidence to exact
  commits and runs; model availability alone does not validate any CI artifact.
- GitHub Trending and community discussions were searched. No reliable
  itemized weekly snapshot or sufficiently corroborated artifact incident was
  found, so neither is used as quantitative evidence.

## Candidates and capability gap

| Candidate | User pain and existing solution | Difference and fit | Choice |
| --- | --- | --- | --- |
| Artifact Run Audit | A green run and an artifact with a familiar name can be unrelated. GitHub exposes each record, but users manually cross-check them. | Reuses Workflow Run Audit and adds exact artifact-run association, expiry, and digest-format checks. Fills the gap between CI-run and Release-asset evidence. | Build. |
| Node 24 action compatibility scan | Action authors may still carry old runtime metadata. GitHub and code search provide simple checks. | Narrower audience; robust YAML parsing would add dependency or fragile heuristics. | Defer. |
| Release-to-CI byte provenance | Teams want proof that tested bytes were published. GitHub artifact digest covers a ZIP, while Release asset digests cover individual files. | Cannot honestly prove equality from metadata alone; needs archive download, safe extraction, and/or attestation. | Defer. |

## Scope

One read-only CLI takes explicit repository, artifact ID, run ID, full commit
SHA, workflow path, and event. It requires a successful run, matching artifact
association, non-expired status, and well-formed digest metadata. It does not
download an archive, inspect files, or infer what tests covered.
