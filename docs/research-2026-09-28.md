# 2026-09-28 research and decision

Window: 2026-09-21 through 2026-09-28. Search terms included Claude Code,
coding agents, MCP, GitHub Actions run API, code review, CI commit SHA, release
verification, GitHub Trending weekly, and developer workflow evidence.

## Signals

- GitHub [changed workflow-run query result counts on September 25](https://github.blog/changelog/2026-09-25-changes-to-query-results-in-the-github-actions-api-and-ui/).
  Count-based scripts should narrow queries. A single-run lookup avoids count
  and pagination assumptions altogether.
- GitHub [expanded Copilot code-review configuration on September 23](https://github.blog/changelog/2026-09-23-copilot-code-review-more-ways-to-request-and-configure-reviews/),
  including automatic reviews on new pushes. A new push can change the exact
  head to which review or CI evidence applies.
- GitHub [retired Node 20 in Actions on September 23](https://github.blog/changelog/2026-09-23-node-20-is-no-longer-available-in-github-actions/).
  This raises workflow-maintenance questions but is narrower than the toolkit's
  cross-language evidence theme.
- Anthropic [released Claude Opus 5.5 on September 22](https://www.anthropic.com/claude-opus-5-5),
  with a stated focus on coding and agents. Better models make exact execution
  evidence more useful; the model release itself is not evidence that a given
  repository's CI ran.
- GitHub's [workflow-run REST endpoint](https://docs.github.com/en/rest/actions/workflow-runs)
  exposes run ID, head SHA, workflow path, event, status, and conclusion. The
  API is an existing source of execution evidence; no extra service is needed.
- GitHub Trending weekly was checked, but the page did not yield a reliable
  itemized snapshot in this environment. Community threads were also searched;
  results were anecdotal and did not drive the decision.

## Candidates and gap

| Candidate | Pain and existing solution | Difference and fit | Decision |
| --- | --- | --- | --- |
| Audit one CI run against a commit | Green runs can be mistaken for evidence about a later SHA. GitHub UI and `gh run view` expose the fields, but require manual cross-checking. | A deterministic read-only exit code fills the gap between Required Check Audit (configuration) and Release Asset Audit (published bytes). | Build today. |
| Scan JavaScript action metadata for `node20` | Maintainers need to update old actions; text search can find simple cases, and YAML syntax needs careful parsing. | Narrow audience and not the toolkit's core evidence chain. | Defer. |
| Review-stage analytics | Teams want to understand review delays; GitHub provides enterprise usage metrics. | Needs enterprise access and metric interpretation; cannot validate here. | Defer. |

## Scope

One CLI, `workflow-run-audit`, checks an explicitly supplied run ID, full SHA,
workflow path, and event, requiring a completed successful run. The API response
is bounded and parsed defensively. It does not infer the newest run, evaluate
job coverage or enforcement, or claim artifact provenance.
