## Existing solutions and actual opportunity

- [agent-scope-guard](https://github.com/manuelsampedro1/agent-scope-guard) already
  checks supplied diffs against allowed paths/globs. We do not claim that scope
  checking is new. Our module reads the actual Git index with NUL framing and
  uses literal file/directory rules, without asking the user to export a diff.
- [agent-spec](https://github.com/ZhangHanDong/agent-spec) already offers staged
  scope guards inside a broader spec/BDD system. Developers needing that system
  should evaluate it. This toolkit starts with a small stdlib gate and a focused
  acceptance fixture rather than a spec engine.
- [lint-staged](https://github.com/lint-staged/lint-staged) runs configured tasks
  on staged files. Its purpose is lint/format execution and it can change files;
  our gate only returns path decisions. A custom lint-staged task could perform
  a similar check; teams with that setup need not replace it.
- [Worktrunk](https://github.com/max-sixty/worktrunk) manages worktrees for
  parallel agent workflows. Worktree isolation helps task ownership; the proposed
  commit still benefits from explicit path review.
- [Open Code Review](https://github.com/alibaba/open-code-review) combines
  deterministic checks and LLM review. This module can precede a review; it does
  not reproduce that system or assess code semantics.
- [Git diff documentation](https://git-scm.com/docs/git-diff) is the implementation
  contract: `--cached`, NUL name/status output, `--no-renames`, `--no-ext-diff`,
  and `--no-textconv`. Git itself supplies the underlying capability; packaging
  it with strict literal scope rules, exit semantics and fixtures is the value.

## Candidate decision

| Candidate | Pain / opportunity | Decision and relation to toolkit |
| --- | --- | --- |
| Staged Scope | Small fix includes unrelated staged paths; need a fast explicit gate with unusual-name and rename coverage | Selected; first ready module in commit handoff |
| Full AI code review | Need high-quality defect findings and calibrated evidence | Existing systems are substantial; broad runtime/eval scope today |
| Version-constraint eval | Agent dependency edits misunderstand package-manager semantics | Useful later, but multiple grammars and oracle choice need a bounded follow-up |
| MCP reconnect inspector | Mid-session tools disconnect with unclear failure state | Official client already adds diagnostics; multi-client live fixtures needed |
| Skill/prompt catalog | Need reusable workflows | Pure prompt collection does not satisfy the runnable-capability requirement |

Local README inventory and authenticated public repository listing found no
existing flagship toolkit. Today's repository establishes that shared entry
point; the selected module is not split into a second repository.

Earlier projects checked: Agent Footprint (filesystem deltas), Agents Scope
(Codex instruction discovery), Plugin Preflight (portable package validation),
Tool Call Ledger (trace lifecycles), SSE Rehearsal (stream faults), and the
forecast/protocol/judge/citation/split/terminology projects. None is imported,
rewritten or republished. File-system deltas and staged commit scope overlap in
motivation but inspect different state. The capability matrix currently has one
ready module; PR ranges and test evidence are known gaps, not shipped features.
